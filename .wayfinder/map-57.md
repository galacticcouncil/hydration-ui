## Destination

A set of decisions — no implementation — that make replacing the Squid-backed **My Recent Activity**, **Open Orders** and **Order History** tabs on `/trade` a straight build: the neckwork query layer in `packages/indexer/src/neckwork/`, the data shapes the new tabs render, how far each tab may drift from its Squid twin, and where `useNeckworkEnabled()` cuts the component tree. Done when nothing is left to decide before someone opens an editor.

## Notes

**Domain.** `apps/main/src/modules/trade/orders/` renders the four-tab panel below the trade chart. `TradeOrders.tsx` switches on the `tab` search param across `MyRecentActivity`, `OpenOrders`, `OrderHistory`, `MarketTransactions`; `TradeOrdersHeader.tsx` owns the tab strip, the `allPairs` toggle and the open-orders badge count. Data comes from Squid through four hooks in `orders/lib/` — `useRoutedTradesData` (recent activity), `useOrdersData` (open orders + order history, one query filtered by `DcaScheduleStatus[]`), `useSwapsData` (market transactions), `usePastExecutionsData` (the DCA details modal's execution list). Presentation is shared: `columns/` (`SwapAmount`, `SwapPrice`, `SwapType`, `SwapStatus`, `DcaOrderStatus`, `SwapMobile`, `AmountMobile`), `SwapDetailsModal`, `DcaOrderDetailsModal`, `PastExecutions/`, `OrdersEmptyState`, `getSwapExplorerLink`.

`TradeOrdersHistory.tsx` is a **different** component — the degraded/legacy path on the `indexer` SDK, chosen in `SwapPageDesktop`/`SwapPageMobile` when `DataProviderStatus` is `DEGRADED`/`OFFLINE`. It is not part of this effort.

Neckwork's own OpenAPI prose says the trades routes were split precisely so "the UI's two tabs map 1:1 onto the API", and the DCA routes carry the status derivation this repo currently does client-side. So the API was built with these tabs in mind — but not identically.

**Decided up front (constraints, not open questions):**

- **New components mounted behind `useNeckworkEnabled()`**, beside the existing ones — the `TradeChartNeckwork` / `FeesAndRevenueNeckwork` pattern already on this branch. Nothing on the Squid path is deleted by this effort.
- **Parity is a preference, not a gate.** Where neckwork can't reproduce a Squid-era cell, the neckwork tab may show less. No reconciliation pass, no synthetic backfill. Reuse the shared `columns/` components and modals wherever the data allows.
- **Scope is three tabs**: My Recent Activity, Open Orders, Order History. Market Transactions stays on Squid for now (see Out of scope).
- **Everything is fetched for the connected wallet**, keyed on `safeConvertSS58toPublicKey(account.address)` — 0x-prefixed lowercase hex, which satisfies neckwork's `^0x[0-9a-f]{40}([0-9a-f]{24})?$` for both substrate public keys and EVM addresses.
- **Query layer follows the pools and fees maps' decisions.** `queryOptions` factories in `packages/indexer/src/neckwork/*.ts` on the shared typed `openapi-fetch` client, mapping inside the package, types only — no zod. The vendored `openapi.json` already carries every route below, so **no codegen refresh is needed**.
- **The endpoints in play**, all confirmed live against `https://hydration-api.neckwork.net`:
  - `GET /v1/trades/routed?participant=&assets=&limit=&offset=` → recent activity. Returns `{ items, totalCount }`; each item is `blockHeight`, `eventIndex`, `extrinsicIndex`, `timestamp`, `swapper`, `operationType`, `assetIn/amountIn`, `assetOut/amountOut`, `dca: { scheduleId } | null`.
  - `GET /v1/dca/schedules?owner=&status=&assets=&limit=&offset=` → open orders and order history. `owner` is **required** (400 otherwise). Server-computed `status: created | completed | terminated | cancelled` — a 1:1 match for `DcaScheduleStatus`, derived from the same signed-extrinsic signal the explorer uses, which retires this repo's `getDcaScheduleStatus` heuristic.
  - `GET /v1/dca/schedules/count?owner=&status=&assets=` → the open-orders tab badge.
  - `GET /v1/dca/schedules/{id}/executions?limit=&offset=` → the DCA details modal. `status: executed | failed | planned`, null amounts on non-executed attempts, plus a top-level `assetIn`/`assetOut`, and an `errorState` **byte-identical to `IndexerErrorState`** so `parseIndexerErrorState`'s zod schema still fits.
- **Confirmed parity gap, measured not assumed:** participant-scoped `/v1/trades/routed` returns **zero** DCA execution rows. Verified against an owner with 101 schedules, 2 live, 914 executions on one of them, and 321 participant trades — none with `dca != null`. On the global feed those same rows carry the *pallet* account as `swapper` (`0x6d6f646c70792f747273727900…` = `modlpy/trsry`), so no participant filter can reach them. The current Squid recent-activity tab mixes market swaps and DCA executions; the neckwork one cannot, without a client-side merge. Has its own ticket.
- **`allPairs` maps to the `assets` param** on all three routes (comma-separated registry ids, matches either side of the pair); pagination maps to `limit`/`offset`. Trades cap `offset` at 10,000; the DCA routes at 1,000,000. Max `limit` is 200 everywhere.
- **`operationType` is frequently null**, including on plainly extrinsic-signed routed trades — the API refuses to guess a batched or hook-dispatched route's fixed side. Any exactIn/exactOut cell must tolerate null.

**Skills every session should consult:** `/grilling` and `/domain-modeling` by default; `/research` for AFK fact-gathering; `/prototype` where a composition is easier to react to than to describe. Repo conventions in `CLAUDE.md` and `packages/indexer/CLAUDE.md` are binding — absolute imports, no test runner, `packages/*` export source TS, `packages/indexer` is a composite project so **build before lint**, `src/*/__generated__/` is committed and never hand-edited, and `--immutable` codegen means neckwork response arrays need `Array.from(...)` before `.map`.

**Autonomous mode.** The map owner asked for this effort to be driven without live grilling: every HITL ticket resolves on the session's own recommended answer, recorded as such on the ticket. No session blocks waiting for a human.

**Planning only** — this map produces decisions, not code. The pull to just write the tabs is the signal the map is done.

## Decisions so far

<!-- one line per closed ticket -->

- [What My Recent Activity shows when neckwork can't see DCA executions](tickets/58-recent-activity-dca-gap.md) — **market swaps only, no client-side merge.** The gap is structural, measured not assumed: **0 DCA rows in 2,117 participant-scoped trades** across 5 owners holding 179 schedules, one with 914 executions. On the global feed those rows name the *pallet* as `swapper`, so no participant filter reaches them. The merge was costed and rejected — 101+ requests to render page 1 for one sampled owner, and two independently-paginated sources cannot produce a coherent page 2. What's lost is specifically the chronological interleaving of swaps and DCA fills; every execution is still on Open Orders / Order History and in the details modal. The `type` column is **dropped** (provably constant), `SwapStatus` stays. Unplanned finding: the schema's `offset` cap of 10,000 on `/v1/trades/routed` **is not enforced** — deep pages work to the end of the set.
- [Open Orders on server-computed DCA schedule status](tickets/59-open-orders-status.md) — **reuse `OrderData` and `DcaScheduleStatus` verbatim; nothing shared changes.** All twelve fields have a counterpart, and two get *better*: `isOpenBudget` reads `isRollingBudget` instead of inferring from `budget === "0"`, and `getDcaScheduleStatus`'s heuristic is **retired** for the server's signed-extrinsic signal — a bug fix riding along. Scaling stays in the app hook (the package can't reach the asset registry); the four-entry status map lives there too. The cancel flow survives untouched. **Invalidation: opt into `QUERY_KEY_BLOCK_PREFIX` and drop `NECKWORK_STALE_TIME`** — all four routes answer `cache-control: max-age=3`, one parachain block, and `useInvalidateOnBlock()` is already mounted app-wide.
- [Order History's status set, and what cancelled means now](tickets/60-order-history-statuses.md) — request `status=completed,terminated,cancelled` (verified: `totalCount` 99 of 101, the 2 `created` excluded). **The three-way distinction reaches the UI at zero cost** — `DcaOrderStatus` already has three branches and three i18n keys, so the neckwork tab is strictly *more* accurate with no component change. Both populations are real: one owner's 101 schedules are 82 completed / 15 cancelled / **2 terminated** / 2 created. Ordering is **already identical** — Squid sorts by max event block desc, neckwork by most recent event first — so no client-side sort. The event-less-last quirk is theoretical (0 of 101 had a null `lastEventAt`).
- [Explorer links from neckwork trade and execution rows](tickets/61-explorer-links.md) — **don't reuse `getSwapExplorerLink`; inline two lines.** After #58 removed DCA rows, only its market branch is reachable, and adapting a shape to reach one sixth of a function is not reuse. The other two link sites already call `neckwork.activityDca` / `activityEvent` inline and need nothing. The `extrinsicIndex` fallback is **effectively dead** — null 0 times in 800 rows — so every row gets a proper `/swap/{block}-{extrinsicIndex}` page. `operationType`, by contrast, is null on **512 of 800**, which rules out ever adding an exactIn/exactOut cell without a "—" state. The `neckwork` name collision is not one: explorer and API, same vendor. Unverifiable by probe — the explorer is an SPA that answers 200 to `/swap/1-999`.
- [PastExecutions on the neckwork executions route](tickets/64-past-executions.md) — **one `useInfiniteQuery` at 200 per page**, keeping the load-all button and looping `fetchNextPage` behind it. Squid's `limit: undefined` "everything" mode is gone: the route caps at 200 and one schedule holds 914. `errorState` is byte-identical to `IndexerErrorState` so `parseIndexerErrorState` and `decodePjsErrorQuery` are untouched; the response's top-level `assetIn`/`assetOut` replace a nested lookup; null amounts on `planned`/`failed` already flow through today's `|| "0"`. `PastExecutionData.id` is **dead** (`VirtualizedList` keys itself) — populate it as `blockHeight-eventIndex`. **The client-side sort goes**: neckwork's order is deterministic where the existing timestamp-only sort is unstable, since planned and executed rows in one block share a timestamp.
- [Shape of the trades and DCA queries in packages/indexer](tickets/62-query-layer.md) — **`trades.ts` + `dca.ts`**, matching the API's tags and the package's one-file-per-domain layout. Params objects (four args each; `feesChartQuery` set the convention), `["neckwork", …]` keys behind `QUERY_KEY_BLOCK_PREFIX` for the three live lists, `staleTime` **omitted** on those and `NECKWORK_STALE_TIME` kept only for executions — which stay off the block prefix, since invalidating an infinite query every 6 s to catch an hourly execution is backwards. The package converts and renames but never scales. **Three fields are dropped from `RoutedTrade`** rather than carried: `swapper`, `operationType`, `dca` — all unread, and a carried field invites someone to build on it. No offset cap: ~21,000 advertised pages is exactly what Squid advertises today.
- [Flag boundary: what the neckwork order panel owns and what stays shared](tickets/63-flag-boundary.md) — **one `TradeOrdersNeckwork` panel, neckwork *first* in the branch** (`DataProviderStatus` tracks Squid's health, not neckwork's — and the chart above it already does this). Three new tab components, two of which differ from their twins **by one import**, because `OrderData` came across intact. `TradeOrdersHeader` stays **single**, with `openOrdersCount` lifted to a prop — 15 lines up one level beats duplicating 120 lines of tab strip to swap one query, and lifting a query is not the shell extraction the fees map ruled out. The `marketTransactions` tab **keeps rendering the Squid component**: hiding it would mean a conditional tab list and a dead `tab=` search value. Empty and disconnected states are free via `enabled: !!account`.
- [Details modals: reuse or fork for the neckwork data shapes](tickets/65-details-modals.md) — **`SwapDetailsModal` needs zero edits**: keep `RoutedTradeData` as the neckwork row type with `status` the constant market literal, and it is structurally assignable. **This corrects #58**, which was right about the column and wrong about the field — dropping a constant column saves table width, dropping a field shared code reads costs a union member and a guard. `DcaOrderDetailsModal` is **not forked** either; it gains one `pastExecutions: ReactNode` prop, and `PastExecutions` splits into a view plus two six-line wrappers. That *is* shell extraction, and the distinction from the fees map's ruling is named: there the renderers were diverging, here they are identical and the seam already exists as the hook's return type.
- [Assemble the neckwork order-tabs implementation plan](tickets/66-implementation-plan.md) — **the handoff artifact.** Four commits, `packages/indexer` built before `apps/main` type-checks, everything net-new inside `TradeOrdersNeckwork/` so deletion is one `rm -r`. **Commit 3 is the entire risk surface** — the only one touching code the Squid path runs. Full file list, what must not change, **no new i18n keys**, and a verification bar naming a real account (`7K5vL7eGtVqYFV5xHirFmQUPUCoKMiEjWjSr4aEyYBCiY17o`: 101 schedules, 2 terminated, 914 executions on one) that exercises the status distinction, load-all paging and rolling budgets at once. Note the toggle default: `VITE_NECKWORK_ENABLED` is `true` in both env files, so **Squid is the case you must select deliberately**.

## Out of scope

- **The Market Transactions tab** and `useSwapsData`. The global `/v1/trades` feed would serve it, but the map owner deferred it. A later effort.
- **The OTC table** (`modules/trade/otc/`) — different data, different pallet, unaffected.
- **`TradeOrdersHistory.tsx` and the degraded/legacy `indexer`-SDK path**, including `useTradeOrdersHistoryData`, `useTradeOrderHistoryEnrichment`, `useOrderTradesData` and `TradeOrderHistoryDetailsModal`. Chosen by `DataProviderStatus`, not by the neckwork flag.
- **Deleting the Squid hooks, queries or components.** They live behind the flag until a later effort removes them.
- **Reconciling neckwork's numbers against Squid** before switching — the new API's figures are accepted as correct.
- **Upstream API changes to neckwork.** Filing a request is fine; waiting on one is not, and no ticket here may depend on one.
